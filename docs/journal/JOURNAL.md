# Журнал проєкту Zapik

Хронологія всього, що відбувається в проєкті: рішення, дії, проблеми, помилки й уроки. Мета — матеріал для ретроспективи.

**Правила ведення**
- Нові записи додаються **вниз**, по одному на сесію або значущу подію.
- Кожен запис містить: дату, хто ініціював (👤 Andrew / 🤖 Claude), що зроблено, рішення з причинами, проблеми й помилки, посилання (коміти, issues, файли).
- Пишемо як є, включно з помилками й хибними припущеннями: це найцінніше для ретро.
- Розділ «Матеріал для ретроспективи» в кінці оновлюється по ходу.

## Матеріал для ретроспективи

### Що спрацювало
- Перехід на правила «факт з джерелом / не знайдено / висновок окремо» швидко виявив помилки в ранніх висновках (Booksy 45%, Klinika XP).
- Відсів ніш через пошук домінантного гравця (Klinika XP, WodGuru) заощадив час до написання коду.
- Тести на інтерфейсі модулів знайшли реальні баги (порожній «сьогодні», пошук за цифрами телефону, мобільний скрол) до користувачів.
- Тікети з критеріями приймання → закриття з коментарем-доказом дають прозору історію в GitHub.

### Що пішло не так
- Ранній ринковий аналіз містив неперевірені цифри (30% Booksy) — довелось виправляти.
- Хибний висновок «токен GitHub недійсний» з однієї перевірки → задачі лежали локально, поки користувач не запитав.
- Очікування щодо скіла `last30days` не збіглися з можливостями хмарного середовища; це забрало час і нерви.
- Частина вимог не перевірена в реальному середовищі (Docker Compose, SMS): хмарне середовище блокує реєстри образів і зовнішні API.

### Відкриті питання / ризики
- Ціна 79 zł/міс і 30 днів безкоштовно — гіпотеза, не перевірена інтерв'ю.
- Торговельна марка «Zapik» не перевірена (UPRP/EUIPO).
- Юридичні тексти — чернетки.
- Меню панелі на телефоні займає 3 рядки.

### Ідеї для покращення процесу
- Перевіряти доступ до інструментів (gh, Docker, мережа) на початку сесії, а не робити висновок з першої помилки.
- Ринкові цифри одразу брати з первинних джерел.
- Інтерв'ю з 15–20 шиномонтажами до наступних великих фіч.
