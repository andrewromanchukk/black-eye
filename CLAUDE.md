# Zapik — інструкції для агента

## Межі задачі (обов'язково)
- Виконуй лише те, що прямо написано в запиті. Якщо прошу «файл X» — змінюю/створюю тільки X.
- Не додавай нових файлів, скриптів, команд Makefile, залежностей чи документації, якщо я їх не назвав.
  Виняток: мінімальні правки, без яких запитане не працюватиме, — і про кожну скажи окремим рядком.
- Ідеї «а ще можна…» не реалізуй. Додай їх у кінець відповіді розділом «Можу зробити далі:» (максимум 3 пункти) і чекай моєї відповіді.
- Якщо запит неоднозначний — постав одне уточнювальне питання до початку роботи, а не обирай ширший варіант.
- Без мого явного дозволу ніколи не: створюй і не змінюй ресурси в AWS, реєстрах образів, GitHub (issues, репозиторії, налаштування); не публікуй образи; не видаляй файли.
- У звіті перелічи всі змінені файли. Якщо файлів більше, ніж я просив, — це помилка, поясни чому.

## Журнал проєкту (обов'язково)
Власник проєкту хоче мати повну історію для ретроспективи. У **кожній** сесії:

1. Перед завершенням сесії (і після кожної значущої події: рішення, реліз, баг, зміна плану) додай запис **вниз** документа `claude/journal-zapik.md` у проєкті Claude «Black-eye» (інструмент Projects: `project_read` → дописати → `project_write`) під заголовком дати `## YYYY-MM-DD (день)`.
2. Формат запису: `### HH:MM · Тема`, далі пункти з 👤 (що попросив/вирішив власник) і 🤖 (що зробив агент), рішення з причинами, проблеми й помилки (включно з власними), посилання на коміти/issues/файли.
3. Онови розділ «Матеріал для ретроспективи» в кінці файлу: що спрацювало, що ні, ризики, ідеї.
4. Пиши українською, чесно, без прикрашань. Час — Europe/Warsaw.
5. Журнал — особистий документ власника: **не** в репозиторії, не в комітах, PR, CI чи будь-де ще. Без доступу до проєкту Claude — сказати про це, а не писати в репо.

## Робочі домовленості
- Остання версія коду завжди в гілці `dev`.
- CI — два workflow. Базовий образ — змінна репозиторію `BASE_IMAGE` (тег + digest).
  - `.github/workflows/pr-checks.yml` — на кожен PR у `main`: збірка образу, unit-тести всередині нього проти Postgres, E2E у браузері. Job `build-and-test` — обов'язкова перевірка в ruleset `main`, не перейменовувати.
  - `.github/workflows/release.yml` — після мерджу в `main`: збірка, unit-тести, push в ECR `720459752381.dkr.ecr.eu-central-1.amazonaws.com/dev/zapik:<git sha>` (теги незмінні; доступ — OIDC, роль у змінній `AWS_ROLE_ARN`). CD (деплой) поки не робимо.
- Стек: Python 3.13, Django 5.2, DRF, PostgreSQL 16 (у контейнері), Docker.
- Мова: UI — польська, код — англійська, документація — українська. Терміни домену — `GLOSSARY.md`.
- Задачі — GitHub Issues (`ready-for-agent`); публікація через `scripts/publish_issues.sh` (REST API).
- Факти про ринок — лише з джерелами; якщо не знайдено, так і писати.
- Тести: `python manage.py test tests` (на PostgreSQL).
