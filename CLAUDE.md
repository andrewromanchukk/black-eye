# Zapik — інструкції для агента

## Журнал проєкту (обов'язково)
Власник проєкту хоче мати повну історію для ретроспективи. У **кожній** сесії:

1. Перед завершенням сесії (і після кожної значущої події: рішення, реліз, баг, зміна плану) додай запис **вниз** файлу `docs/journal/JOURNAL.md` під заголовком дати `## YYYY-MM-DD (день)`.
2. Формат запису: `### HH:MM · Тема`, далі пункти з 👤 (що попросив/вирішив власник) і 🤖 (що зробив агент), рішення з причинами, проблеми й помилки (включно з власними), посилання на коміти/issues/файли.
3. Онови розділ «Матеріал для ретроспективи» в кінці файлу: що спрацювало, що ні, ризики, ідеї.
4. Пиши українською, чесно, без прикрашань. Час — Europe/Warsaw.
5. Комітить журнал разом із роботою (або окремим комітом) у гілку `dev`.

## Робочі домовленості
- Остання версія коду завжди в гілці `dev`. CI/CD поки не робимо.
- Стек: Python 3.13, Django 5.2, DRF, PostgreSQL 16 (у контейнері), Docker.
- Мова: UI — польська, код — англійська, документація — українська. Терміни домену — `GLOSSARY.md`.
- Задачі — GitHub Issues (`ready-for-agent`); публікація через `scripts/publish_issues.sh` (REST API).
- Факти про ринок — лише з джерелами; якщо не знайдено, так і писати.
- Тести: `python manage.py test tests` (на PostgreSQL).
